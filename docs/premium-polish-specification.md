# Premium Polish Specification

## 1. Purpose

Improve the current DAMAC Islands 2 landing page so it feels more refined, elegant, smooth, and custom-designed while preserving the existing wireframe.

The page must remain suitable for an economical real estate website, but the final result must be strong enough to present in a professional portfolio.

This is a visual refinement pass, not a redesign.

---

## 2. Primary Objective

Raise the perceived quality of the current implementation through:

- stronger typography
- better spacing
- more controlled color usage
- cleaner components
- softer visual treatment
- improved consistency
- subtle premium details
- reduced visual noise
- refined interactions

The result must feel calm, intentional, polished, and modern.

It must not feel like a generic landing page template.

---

## 3. Fixed Constraints

The existing wireframe is frozen.

The agent must not:

- add new page sections
- remove existing sections
- change the order of sections
- change the main content structure
- rebuild the page layout
- replace the current grid structure
- introduce a new visual concept
- redesign the page from scratch
- change the project content unless required for minor UI consistency
- replace or search for images during this phase
- make image quality the focus of this phase
- introduce heavy animation libraries
- use excessive decorative effects
- add visual elements that change the wireframe

The agent may:

- improve styles inside the current structure
- refine spacing and alignment
- improve typography
- refine colors, borders, shadows, and radii
- improve component consistency
- remove unnecessary decorative noise
- add subtle visual details
- improve hover, focus, reveal, and scroll behavior
- adjust dimensions when required to improve balance
- simplify repeated visual treatments
- improve responsiveness without altering the wireframe

---

## 4. Visual Direction

The target visual character is:

- elegant
- premium
- soft
- clean
- restrained
- modern
- trustworthy
- editorial
- high-end without being extravagant

The page must not feel:

- flashy
- over-designed
- crowded
- heavily animated
- overly rounded
- excessively shadowed
- like a SaaS template
- like a prebuilt real estate theme
- artificial or decorative without purpose

Premium quality must come from control, spacing, typography, consistency, and restraint.

---

## 5. Design Principles

### 5.1 Restraint

Use fewer visual effects, but make each effect intentional.

Do not use gold, shadows, borders, gradients, or animation everywhere.

### 5.2 Consistency

All repeated components must follow one system.

No component must look approximately similar to another. Repeated components must be clearly related.

### 5.3 Hierarchy

The user must immediately understand:

1. project name
2. project positioning
3. price and enquiry action
4. project benefits
5. project lifestyle
6. location
7. final contact action

### 5.4 Breathing Space

The page must feel spacious without becoming empty or inefficient.

### 5.5 Softness

The final interface must feel smoother through:

- softer contrast transitions
- more controlled spacing
- subtle borders
- restrained shadows
- refined radii
- gentle motion

---

## 6. Global Design System

Create or refine a clear visual system before adjusting individual sections.

### 6.1 Color Roles

Keep the existing SMB brand colors:

- Navy Blue: `#0a2342`
- Golden Yellow: `#f9ba3f`

Use them by role, not randomly.

#### Navy

Use navy for:

- primary text
- dark sections
- primary buttons
- strong structural contrast
- footer
- selected emphasis

Do not use multiple unrelated navy shades unless they are derived systematically.

#### Gold

Use gold sparingly.

Use it for:

- eyebrow accents
- short divider lines
- selected icons
- small highlights
- focused states
- important numbers or labels
- primary CTA only when necessary

Do not use gold as a large decorative surface.

Do not use gold on too many components at the same time.

#### Neutral Backgrounds

Replace repetitive pure white backgrounds with a controlled neutral system.

Use a small set of backgrounds such as:

- warm white
- soft off-white
- very light warm gray
- restrained pale sand
- navy

The contrast between adjacent sections must be subtle but visible.

Do not introduce multiple random neutral colors.

### 6.2 Text Colors

Define clear roles for:

- primary heading text
- body text
- muted supporting text
- labels
- text on dark backgrounds
- interactive text

Body text must not be too dark or too faint.

Muted text must remain readable.

### 6.3 Border System

Use one subtle border color for light surfaces and one for dark surfaces.

Borders must be low contrast.

Avoid visible gray boxes around every component.

### 6.4 Shadow System

Use no more than three shadow levels:

- subtle surface
- elevated card
- floating element

Shadows must have:

- low opacity
- wide blur
- soft edges
- little or no visible blackness

Remove heavy or compact shadows.

### 6.5 Radius System

Create a limited radius scale.

Recommended roles:

- small: inputs and compact controls
- medium: buttons and small cards
- large: major cards and images

Do not use different arbitrary radius values across the page.

Do not make every element excessively rounded.

---

## 7. Typography

Typography is the highest-priority improvement.

### 7.1 Font Use

Keep the current primary typeface unless there is a clear technical or visual problem.

Do not introduce multiple font families.

Use font weight, size, spacing, and line height to create hierarchy.

### 7.2 Heading Hierarchy

Refine all heading levels as one system.

Requirements:

- headings must feel confident but not heavy
- avoid excessive bold weights
- use tighter visual control on large headings
- keep comfortable line height
- prevent headings from becoming too wide
- use responsive sizing
- preserve clear distinction between heading levels

The hero title must be the strongest typographic element on the page.

Section headings must be consistent in:

- size behavior
- line height
- weight
- maximum width
- spacing above and below

### 7.3 Body Copy

Improve readability by:

- limiting text line length
- increasing line height
- reducing overly dark body color
- separating paragraphs clearly
- avoiding dense text blocks

Body text must feel calm and editorial.

### 7.4 Eyebrows

All section eyebrows must use one signature style.

Use:

- small uppercase text
- restrained letter spacing
- a short gold line or equivalent minimal accent
- consistent spacing below

Do not allow different eyebrow styles between sections unless required by light and dark backgrounds.

### 7.5 Numbers and Prices

Prices, statistics, areas, dates, and bedroom counts must use a consistent numeric style.

The number must be visually dominant.

The supporting label must be quieter.

---

## 8. Spacing and Rhythm

Perform a full spacing audit.

### 8.1 Section Spacing

Standardize vertical padding across sections.

Use a small scale such as:

- compact section
- standard section
- large section

Do not assign unrelated padding to each section.

The visual rhythm must remain smooth from top to bottom.

### 8.2 Content Spacing

Normalize spacing between:

- eyebrow and heading
- heading and paragraph
- paragraph and CTA
- cards
- icon and text
- label and input
- section heading and section content

### 8.3 Container Alignment

Verify that all major content aligns to the same container edges.

Avoid small accidental shifts between sections.

### 8.4 Grid Gaps

Standardize horizontal and vertical grid gaps.

Related card groups must use the same gap logic.

### 8.5 Mobile Spacing

Reduce spacing proportionally on smaller screens without making the interface cramped.

## 22. Motion and Interaction

Use subtle motion only.

Do not add GSAP or another heavy animation library for this polish pass.

### 22.1 General Motion Rules

- use smooth easing
- use short or medium duration
- avoid bouncing
- avoid large translations
- avoid aggressive scaling
- avoid animating every element
- respect `prefers-reduced-motion`

### 22.2 Allowed Effects

- subtle button hover
- slight card lift
- gentle image scale
- underline or color transition on links
- smooth input focus
- restrained reveal on scroll
- soft header state transition

### 22.3 Scroll Reveals

If reveal animations already exist:

- reduce travel distance
- use consistent duration
- stagger only related groups
- avoid long delays
- ensure content remains usable without JavaScript

---

## 27. Technical Implementation Rules

- Work only inside the current preview implementation.
- Preserve the existing HTML structure unless a minor markup adjustment is required for styling, accessibility, or consistency.
- Do not rebuild sections.
- Do not replace working functionality.
- Do not change form field names or IDs.
- Do not remove accessibility attributes.
- Do not add dependencies unless absolutely necessary.
- Prefer CSS improvements over JavaScript.
- Keep JavaScript small and purposeful.
- Reuse design tokens through CSS custom properties.
- Remove obsolete or duplicate CSS after the polish pass.
- Avoid one-off values when a shared token can be used.
- Keep the final CSS maintainable and clearly structured.

## 29. Acceptance Criteria

The task is complete only when all conditions below are met.

### Structure

- The wireframe remains unchanged.
- All existing sections remain in the same order.
- No new section has been added.
- No existing section has been removed.

### Visual Quality

- Typography hierarchy is stronger.
- The page feels softer and more refined.
- Section spacing is consistent.
- Card styling is controlled.
- Gold usage is restrained.
- Background transitions create subtle rhythm.
- Borders and shadows are not excessive.
- Buttons and forms follow one design system.
- The page no longer feels like a generic template.

### Interaction

- Hover states are subtle.
- Focus states are accessible.
- Scroll reveals are restrained.
- Motion respects reduced-motion preferences.

### Responsive Quality

- Desktop, tablet, and mobile remain functional.
- No layout overflow exists.
- Spacing scales correctly.
- Typography remains balanced.
- Forms and buttons remain easy to use.

### Technical Quality

- No unnecessary dependency has been added.
- CSS uses shared tokens.
- Duplicate styles are removed.
- Existing functionality remains intact.
- Accessibility is preserved or improved.
