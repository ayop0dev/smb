# Mandatory Changes

Only the following are marked NO — the sections that genuinely do not fit their content, independent of any repetition or rhythm concern:

1. **Developer Archive Hero (thin variant) — 20 pages.** The hero's biography paragraph duplicates the "Developer Overview" section's paragraph directly below it, word for word. This is a single root cause shared with item 3 below (both draw from the same underlying biography text), not two independent problems.
2. **Contact: "Visit or Speak With Us."** Restates content already given twice on the same page (the "Ways to Contact Us" tile grid above it, and the page's own closing CTA below it) with no new information. No presentation of this exact content, at this exact point in the page, is the natural choice, because the content itself is not adding anything new.
3. **Developer Archive: "Developer Overview" — 20 pages.** The Split Story format is a sound, proven fit for biography content in principle (About's own introduction proves this), but as implemented, this section's text is identical to the hero's text one scroll above it (item 1). This is the same underlying issue as item 1, surfacing in a second location.

Note that items 1 and 3 are, in practice, **one content-architecture problem appearing in two presentation slots on the same 20 pages** — the biography text needs to do two different jobs (a short hero statement, and a fuller overview) but currently does the same job twice.

---

# Safe Improvements

Sections marked ACCEPTABLE — reasonable as they stand, with a plausible alternative that would not represent a correction, only a variation. Not worth changing now:

1. **Home: "Why SMB"** — grid vs. list is a style choice for this content, not a mismatch.
2. **About: "Mission & Vision"** — a two-item grid is a near-universal, valid convention for this exact content pairing.
3. **About: "Our Values"** — same reasoning as Home's "Why SMB."
4. **Contact: "Map"** — the placeholder presentation is an honest match for currently-placeholder content; only worth revisiting once real map data exists.
5. **Project Page: "Location & Connectivity"** — a working fit; a lighter treatment is plausible but not a correction.

(Note: item 1 and item 5 on this list are the same two sections the Minimal Presentation Improvement Plan separately recommended changing — that plan's reasoning was about page rhythm, this document's is about pure content fit. Both conclusions can be correct at once: a section can be a fine independent fit for its content while still being worth varying for the sake of the page it sits on. This document does not overrule that plan; it simply confirms that neither section is a genuine content-presentation mismatch on its own terms.)

---

# Final Recommendation

**1. How many sections should remain exactly as they are?**
30 of 38 (the YES rows) should not be touched at all. A further 5 (the ACCEPTABLE rows) should also remain untouched for now, for a combined 35 of 38 requiring no action.

**2. How many sections truly deserve change?**
3 rows are marked NO, but they reduce to 2 distinct problems: the duplicated developer-biography text (appearing in both the Developer Archive hero and the Developer Overview section, across 20 pages), and Contact's redundant "Visit or Speak With Us" section.

**3. If the project had only one day available, which changes would you actually implement?**
The duplicated developer-biography issue. It is a single root cause, lives in one shared template file, and its correction benefits all 20 developer-archive pages at once — the highest leverage available among the three flagged items. If time remains within the same day, Contact's redundant "Visit or Speak With Us" section is the natural second pick: it is confined to one page and one section, and is independently understandable without depending on the first fix.

**4. Which improvements should intentionally be postponed?**
All 5 Safe Improvements (Home's "Why SMB," About's "Mission & Vision," About's "Our Values," Contact's "Map," and the Project Page's "Location & Connectivity"). None of them represent a content-presentation mismatch — they are legitimate as they stand, and any change to them would be a style preference rather than a correction, which does not meet this evaluation's bar for action.
